# Task B - Fulfilment Split Optimiser

在仓库根目录运行：

```powershell
Get-Content B/examples/sample.in | .venv/Scripts/python.exe -m B.main
.venv/Scripts/python.exe -m pytest B/tests -q
```

## 状态表示

先按仓库 ID 排序。`D[i][q]` 表示只使用第 i 个及之后的仓库，恰好发出 q 件时最优的 `(仓库数量, 总费用)`。不可达状态用 None；初始 `D[W][0]=(0,0)`，其余需求不可达。

设当前仓库库存为 s、固定费为 f、单价为 u。转移比较：

- 不使用当前仓库：取 `D[i+1][q]`。
- 分配 x 件：下一层状态的仓库数加 1、费用加 `f+x*u`，其中 `1 ≤ x ≤ min(s,q)`。

为避免逐个枚举 x，令 `t=q-x`，用单调队列维护窗口 `max(0,q-s)..q-1` 内最小的 `(count, cost-t*u)`，再分别加 1 和 `f+q*u`。每层只读取下一层，不会重复使用同一仓库。实现只使用 Python 标准库。

## 同优方案的取舍策略

首先比较仓库数量，再比较总费用；两者都相同时，比较按 ID 排序的非零 `(warehouse_id, quantity)` 列表。

DP 保存前两项目标的最优值。重建时按 ID 升序、数量从小到大尝试，仅接受“当前仓库的贡献 + 下一后缀最优值 = 当前目标”的候选，选中第一个后继续重建后缀。每一步都选能够完成最优目标的最小项，因此得到最小字典序。

例如 A、B 各有 10 件且费用均为 0，订单需要 12 件，两仓方案费用都一样；应选 `[(A,2),(B,10)]`。数量按整数比较，未使用的仓库不放进列表。

## 时间复杂度和空间复杂度

排序 O(W log W)。单调队列每个状态最多入队、出队一次，DP 为 O(WQ)；重建只向后遍历仓库，每仓最多尝试 Q 个数量，也为 O(WQ)。

总时间 **O(WQ+W log W)**，保存完整后缀表占用 **O(WQ)** 空间。输入缓存另占 O(L)，L 为输入长度；ID 比较按固定长度估算。

## 测试与输入约定

[test_optimizer.py](tests/test_optimizer.py) 覆盖库存不足、零库存、仓库数量优先、费用和平局比较；[test_scale.py](tests/test_scale.py) 覆盖 W=30、Q=2000 的大数量情况。另有 5000 组独立穷举差分，比较完整三级目标。

仓库 ID 按区分大小写的 Unicode 码点顺序排序，重复 ID 拒绝。输入错误写 stderr、退出码 2；合法但库存不足输出 -1。可行结果按题目格式输出仓库数、费用及排序后的分配。
